# `oc` help, errors, colour and icons — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give `oc` per-command help, errors that name the fix, validation before sudo, and coloured icon-led output that is plain ASCII whenever it is not going to a terminal.

**Architecture:** Three primitives (`is_color`, `is_utf8`, and a `ok/warn/fail/err/usage_err` family) drive every message. Each command owns a `help_<cmd>()` function, so `oc help X` and `oc X --help` print the same text from one place. Every command validates its arguments before calling `need_docker`.

**Tech Stack:** POSIX `sh`, `awk`, `jq` (already required), `node:test` shim harness in `tests/oc.test.mjs`.

**Spec:** `docs/superpowers/specs/2026-11-15-oc-help-design.md`

## Global Constraints

- `bin/oc` stays POSIX `sh` with `set -eu`; no new runtime dependency.
- Colour appears only when stdout is a TTY, `NO_COLOR` is unset or empty, and `TERM != dumb`. `NO_COLOR` present and non-empty always wins (no-color.org).
- Icons are the single-width glyphs `✓`, `!`, `✗`; ASCII fallback `ok`, `!`, `x` when the locale is not UTF-8 or `OC_ASCII=1`.
- No ANSI escape may reach a pipe, a file, or a test capture.
- Exit codes unchanged: 0 success, 1 environment or check failure, 2 usage error.
- Validation precedes `need_docker` in every command.
- One source of truth for `.env` rules: `scripts/check-env.sh` (never re-implement in `bin/oc`).
- One source of truth for help text: `help_<cmd>()` (never repeat a usage string in `usage()`).

## Review Focus

1. **Piping output into a file or `grep`** must produce no escapes and no icons — plain text only. Test in Task 1.
2. **`oc <cmd> --help`** must not touch docker, must exit 0, and must print exactly what `oc help <cmd>` prints. Test in Task 2.
3. **A typo or a missing flag value** must fail with exit 2 before any sudo, on a machine with no docker group. Test in Task 3.
4. **Two terminals at once**: help and errors write no files, so concurrent runs cannot interleave state; `--json` output must be one object per line, never a half-written stream. Test in Task 4.
5. **`doctor --json` with zero FAILs** must still validate as JSON and carry eight checks. Test in Task 4.

### Task 1: Output primitives

**Files:** Modify `bin/oc`; Test `tests/oc.test.mjs`

**Interfaces:**
- Produces: `is_color()` → 0/1, `is_utf8()` → 0/1, `icon_pass/icon_warn/icon_fail` (strings set once at startup), `ok <text>`, `warn <text>`, `fail <text>` (doctor/status verdicts), `err <text>` (stderr + exit 1), `usage_err <cmd> <text>` (stderr + `hint: oc help <cmd>` + exit 2), and the colour variables `C_GREEN C_YELLOW C_RED C_BOLD C_RESET` (empty when colour is off).

- [ ] **Step 1: Write failing tests** — `piped output is plain`: `oc(["help"])` → stdout has no `\u001b`; `no colour when NO_COLOR is set` — with `env NO_COLOR=1`; `OC_ASCII=1 forces the ascii icons` → `oc(["doctor"])` with `OC_ASCII=1` and `OC_NO_SUDO=1` stdout has no `✓`/`✗` and does contain `PASS`.
- [ ] **Step 2: Run** `node --test tests/oc.test.mjs` → the three fail (icons are unconditional today; no ASCII switch).
- [ ] **Step 3: Implement** the primitives; `is_color` checks `[ -t 1 ]`, `${NO_COLOR:-}` empty, `TERM != dumb`. `is_utf8` greps `LC_ALL/LC_CTYPE/LANG` for `UTF-8`. `err`/`usage_err` print `oc: <text>`, and `usage_err` adds `hint: oc help <cmd>`.
- [ ] **Step 4: Run** → PASS.
- [ ] **Step 5: Commit** `feat(oc): colour, icons and error primitives`.

### Task 3: Validation before sudo, and suggestions

**Files:** Modify `bin/oc`; Test `tests/oc.test.mjs`

**Interfaces:**
- Consumes: `usage_err`, `help_<cmd>`.
- Produces: `did_you_mean <word>` (prints `did you mean: <cmd>?` or nothing), every command parsing flags into locals and calling `usage_err` on unknown flags, and `need_docker` moved after validation in `up`, `down`, `restart`, `status`, `pair`, `shell`, `logs`, `config`, `doctor`.

- [ ] **Step 1: Write failing tests** — `unknown command suggests`: `oc(["docotr"])` exit 2, stderr contains `did you mean: doctor`, stdout empty; `unknown flag fails before sudo`: `oc(["up","--nope"])` exit 2, `CALL docker` absent; `missing flag value fails before sudo`: `oc(["logs","--since"])` exit 2 with `--since needs a value`; `no .env fails with a fix line`: temp repo without `.env`, `oc(["up"])` exit 1, stderr has `fix: ./setup.sh`, no docker call; `no ARG for restore`: `oc(["restore"])` exit 2 with `usage: oc restore`.
- [ ] **Step 2: Run** → fail.
- [ ] **Step 3: Implement** the suggestion (`awk` distance over the command list, threshold 2), the flag validators, and reorder `need_docker` to the last step of each command. Errors carry `hint:` and `fix:` lines: no `.env` → `fix: ./setup.sh`; stale image → `fix: ./bin/oc up --build`; daemon unreachable → `fix: sudo systemctl start docker` (or add to the docker group).
- [ ] **Step 4: Run** → PASS.
- [ ] **Step 5: Commit** `feat(oc): validate before escalating, and suggest near-miss commands`.
