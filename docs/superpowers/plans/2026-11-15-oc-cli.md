# `oc` CLI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship `bin/oc`, a POSIX-sh dispatcher for the eleven routine jobs in this repo, plus `oc doctor`, which detects in seconds the failures that have actually bitten this project.

**Architecture:** One script with a `case` dispatch table and one `run()` that prints, optionally echoes (`OC_VERBOSE=1`), and re-execs through `sudo` when the daemon is not reachable. Every command delegates to the existing script or compose invocation that owns it; nothing is reimplemented. `doctor` is a read-only sequence of numbered checks that print a table and exit 1 if any FAILs. Tests drive the script with a fake `docker`/`curl`/`git`/`sudo` on `PATH`, so they run without a daemon.

**Tech Stack:** POSIX `sh`, `docker compose` v2 (5.7.0 here, `up --wait` available), `node:test` for tests, `jq` (already required by the project).

**Spec:** `docs/superpowers/specs/2026-11-15-oc-cli-design.md`

## Global Constraints

- `bin/oc` is POSIX `sh` (`#!/bin/sh`, `set -eu`), like every script in `scripts/`.
- No new runtime dependencies: only what the repo already requires (`docker`, `docker compose` v2, `git`, `jq`, `node` for tests).
- Repo root is resolved from the script's own path (`CDPATH= cd -- "$(dirname -- "$0")/.."`), never from `$PWD`.
- Every subcommand is read-only or idempotent and writes no files of its own; no lock files, no caches.
- `down --volumes` must refuse to run without `--yes`.
- Sudo is re-exec of the same command line; `OC_NO_SUDO=1` disables it and exits 1 with the reason.
- Exit codes: `0` success, `1` check failed or environment wrong, `2` usage error.
- `oc doctor` never mutates: no compose up/down, no file writes.
- The `Dockerfile` label is `org.opencode-docker.policy-sha`, value = `sha256sum policy/opencode.json` (first field).

## Review Focus

1. **`oc` invoked from another directory** (e.g. `cd /tmp && ~/opencode-docker/bin/oc status`) must operate on the repo, not on `$PWD` — test in Task 1.
2. **A second terminal running `oc up` while one is already up** must not error or rebuild: `up` is idempotent — test in Task 2.
3. **`oc down --volumes` typed without `--yes`** must refuse and touch nothing, because that command destroys sessions — test in Task 2.
4. **No docker daemon** (fresh machine, or `no_new_privs` terminal) must produce a clear FAIL in `doctor` and a clear sudo message elsewhere, never a hang — test in Tasks 1 and 5.
5. **Paths with spaces** in `PROJECTS_DIR` or a backup directory must survive quoting — test in Task 3.

- [ ] **Step 3: Implement the skeleton in `bin/oc`**

`#!/bin/sh`, `set -eu`; `REPO=$(CDPATH= cd -- "$(dirname -- "$0")/.." && pwd)`; `cd "$REPO"`.

`run() { [ "${OC_VERBOSE:-0}" = 1 ] && printf '+ %s\n' "$*" >&2; "$@"; }`

`need_docker()`: `docker info >/dev/null 2>&1 && return 0`; if `OC_NO_SUDO=1`, print to stderr `oc: cannot reach the docker daemon. Add this user to the docker group, or run the command without OC_NO_SUDO.` and exit 1; otherwise `exec sudo -- "$0" "$@"` (with `OC_NO_SUDO=1` in the environment so a second failure cannot loop).

`usage()` prints a two-column table (command, what it runs) and the two environment variables.

Dispatch: `help|--help|-h` → usage 0; `version` → print `oc <git describe --tags --always>`, repo path, compose version; unknown → stderr + usage 2.

Skeleton branches for this task: `status` only (`run docker compose ps`).

Expected: PASS, 5 tests.

### Task 2: Lifecycle commands

**Files:**
- Modify: `bin/oc`
- Test: `tests/oc.test.mjs`

**Interfaces:**

- Produces: `up [--build]`, `down [--volumes] [--yes]`, `restart`, `pair`, `shell [cmd…]`, `logs [-f] [--since W]`.

- [ ] **Step 1: Write the failing tests**

- `up waits for health` — `oc(["up"])` → `SHIM_LOG` has `compose up -d --wait --wait-timeout 90`.
- `up --build builds first` — `oc(["up","--build"])` → log has `compose up -d --build --wait --wait-timeout 90`.
- `up is idempotent` — call `oc(["up"])` twice → both code 0, second log identical in shape (no `--force-recreate`, no `down`).
- `down refuses volumes without --yes` — `oc(["down","--volumes"])` → code 1, stderr contains `--yes`, `SHIM_LOG` empty.
- `down --volumes --yes proceeds` — log has `compose down --volumes`.
- `pair mints through the service` — log has `compose exec -T opencode opencode pair --url http://opencode.localhost:8080`.
- `shell defaults to bash and forwards args` — `oc(["shell","ls","-l"])` → log has `compose exec opencode sh -lc "bash"`? No: `oc(["shell"])` → `compose exec opencode bash`; `oc(["shell","ls -l"])` → `compose exec opencode sh -lc "ls -l"`.
- `logs forwards -f and --since` — `oc(["logs","-f","--since","2h"])` → log has `compose logs -f --since 2h opencode`.

- [ ] **Step 2: Watch them fail** — `node --test tests/oc.test.mjs` → the new cases fail with `unknown command`.

- [ ] **Step 3: Implement the branches**

`up`: parse `--build`, then `need_docker`, `run docker compose up -d ${BUILD:+--build} --wait --wait-timeout 90`, then print `→ http://opencode.localhost:8080 (pair with: oc pair)`.

`down`: collect `--volumes`/`--yes`; if `--volumes` and not `--yes`, stderr `oc: --volumes destroys sessions, snapshots and the container's credentials. Re-run with --yes if that is what you want.` exit 1.

`restart`: `run docker compose up -d --force-recreate --wait --wait-timeout 90` (recreate, not `restart`, because nginx caches the upstream IP).

`pair`: `run docker compose exec -T opencode opencode pair --url http://opencode.localhost:8080`.

`shell`: no args → `run docker compose exec opencode bash`; else `run docker compose exec opencode sh -lc "$*"`.

`logs`: pass `-f`, `--since W` through, then `opencode`.

### Task 4: Policy label and doctor checks 1–4

**Files:**
- Modify: `Dockerfile`, `bin/oc`
- Test: `tests/oc.test.mjs`

**Interfaces:**
- Consumes: `run()`, `need_docker()`, `config` logic from Task 3.
- Produces: `doctor` printing `<PASS|WARN|FAIL> <n> <text>`, a trailing `summary: N passed, N warned, N failed`, exit 1 if any FAIL; helpers `pass/warn/fail`.

- [ ] **Step 1: Add the label and its test**

In `Dockerfile`, after the `COPY policy/opencode.json` / `chmod` lines:
`LABEL org.opencode-docker.policy-sha="${POLICY_SHA}"` with `ARG POLICY_SHA=unknown` declared above, and a comment that `scripts/build-hint.sh` cannot compute it at build time — the build command passes `--build-arg POLICY_SHA=$(sha256sum policy/opencode.json | cut -d' ' -f1)`. `oc up --build` computes this automatically.

Failing test: `dockerfile carries the policy digest label` — read `Dockerfile`, assert it contains `LABEL org.opencode-docker.policy-sha=` and that `bin/oc` contains `--build-arg POLICY_SHA=` (grep), so `oc up --build` cannot drift from the plan.

- [ ] **Step 2: Watch it fail** — `node --test tests/oc.test.mjs`.

- [ ] **Step 3: Implement doctor checks 1–4**

`doctor()` header: `need_docker` first (so a daemon-less machine fails once, clearly).

1. `.env`: exists → else FAIL `no .env (run ./setup.sh)`; mode `600` else WARN; `OPENCODE_PASSWORD` empty/`change-me` → FAIL.
2. `HOST_HOME`/`PROJECTS_DIR` set; `PROJECTS_DIR` = `/` or `$HOME` → FAIL; not a directory → WARN.
3. `docker compose config -q` → FAIL on non-zero.
4. Staleness: `NEWEST=$(git log -1 --format=%ct -- Dockerfile overlay.mjs entrypoint.sh commands policy seccomp bin)`; `BUILT=$(docker image inspect -f '{{.Created}}' opencode-docker-opencode:local)` converted with `date -d`; if `BUILT < NEWEST` → FAIL `image is older than <file>: oc up --build`.
